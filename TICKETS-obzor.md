## О-10 · Автоматические проверки — ✅ на сайте 22.10.2026

`.github/workflows/checks.yml`: на каждый пуш в любую ветку и на каждый
пул-реквест GitHub запускает формат, линтер, типы и тесты — те же
четыре команды, что разработчик гоняет руками. Сборки нет: ей нужна
база, а сайт и так собирает Vercel.

Как пользоваться: перед выкладкой в `main` смотреть, что проверка на
этом коммите в ветке зелёная. Запретить выкладку без зелёной проверки
можно в GitHub → Settings → Branches (правило для `main`, «Require
status checks»), но тогда прямой пуш в `main` перестанет работать —
выкладывать придётся через пул-реквест. Пока не включено.

Первый прогон упал на типах: `PageProps`/`LayoutProps` Next создаёт сам
при запуске сайта, на чистой машине их нет. Теперь `npm run typecheck`
начинается с `next typegen` (ему нужен `DATABASE_URL` — в CI заглушка).
Второй прогон (`e8cc2a7`) — все шаги зелёные. Правило выкладки записано
в `.ai/rules/workflow.md`.

## О-8, О-9 · Картинки через Cloudflare — ✅ на сайте 22.10.2026

Панель Cloudflare настроена заказчиком 22.10.2026, в Vercel заданы
`NEXT_PUBLIC_R2_PUBLIC_URL=https://img.berlant-art.com` и
`IMAGE_RESIZE=cloudflare`. У О-8 кода нет: свой адрес бакету и
`Cache-Control` на год задаются в панели. Все шаги —
[docs/cloudflare-kartinki.md](./docs/cloudflare-kartinki.md).

Проверено на настоящем Cloudflare до выкладки:

- по `img.berlant-art.com` отдаётся тот же файл, что по `r2.dev`
  (совпадает побайтно);
- все 9 ширин сайта (64…2560) отдаются копиями в AVIF; фото 491 КБ:
  64px — 1,5 КБ, 384px — 33 КБ, 640px — 90 КБ, 2560px — 272 КБ;
- исходники и копии хранятся в кеше Cloudflare (`HIT`) и уходят
  браузеру с `Cache-Control: max-age=31536000`;
- ответ «не найдено» не хранится (`BYPASS`). Первая версия правила его
  хранила год — добавлена строка Status code TTL, инструкция исправлена;
- сборка с боевыми переменными: 201 страница работы из 204 берёт фото
  с `img.berlant-art.com` через нарезку (у трёх фото из `public/`),
  ни одной ссылки на `r2.dev`.

Адрес `r2.dev` не выключен и спешить с этим незачем: на него ещё
ссылаются картинки в поиске Google и превью ссылок, уже разосланных
в мессенджерах. Выключать — когда Google переиндексирует картинки
(Search Console → страницы с картинками на `img.berlant-art.com`).

- `lib/image-resize.ts` — адрес копии
  `…/cdn-cgi/image/width=…,quality=85,format=auto,fit=scale-down,onerror=redirect/<ключ>`.
  Картинки из `public/` и адреса `r2.dev` остаются как есть;
- `lib/image-loader.ts` — обёртка, которую требует Next (`images.loaderFile`);
- `lib/env.ts` — `IMAGE_RESIZE` и проверка: с адресом `r2.dev` сборка
  падает с объяснением, а не молча ничего не режет;
- тесты — `lib/image-resize.test.ts`.

Проверено на собранном сайте с подставным сервером, который режет так же,
как Cloudflare. Все 30 картинок показались, ни одной ошибки. Какие копии
просит сайт:

| Где                    | Телефон 390px ×3 | Ноутбук 1280px | Ретина 1440px ×2 |
| ---------------------- | ---------------- | -------------- | ---------------- |
| плитка галереи         | 640              | 384 и 640      | 828 и 1920       |
| картина на странице    | 1200             | 1920           | 2560             |
| миниатюра «Все работы» | 384              | 128            | 256              |

Тестовые фото те же, что в замере обзора; вес на них — было → стало: галерея
6,7 МБ → 1,1 МБ (телефон) и 0,6 МБ (ноутбук), «Все работы» 4,6 МБ → 0,3 МБ.
Картина и её размытый фон на странице работы — один и тот же запрос.

**Не проверено отсюда:** настоящий Cloudflare (сеть среды его не пускает)
и `onerror=redirect` при исчерпанном лимите — это проверка шагов 2 и 5
инструкции. При CSP (О-15) не забыть `img-src` для `img.berlant-art.com`.

## О-14 · Защитные заголовки — ✅ на сайте 22.10.2026

`next.config.ts`, `securityHeaders` — на каждый ответ сайта:

| Заголовок                                                      | Зачем                                                  |
| -------------------------------------------------------------- | ------------------------------------------------------ |
| `X-Frame-Options` + `frame-ancestors 'self'`                   | сайт и вход в админку нельзя встроить в чужую страницу |
| `X-Content-Type-Options: nosniff`                              | браузер не угадывает тип файла, а верит заголовку      |
| `Referrer-Policy: strict-origin-when-cross-origin`             | чужому сайту по ссылке уходит только адрес, без пути   |
| `Permissions-Policy: camera=(), microphone=(), geolocation=()` | страница не может включить то, чем сайт не пользуется  |

Плюс `poweredByHeader: false` — в ответах больше нет «X-Powered-By: Next.js».
HSTS не добавлен — по всей видимости, его ставит Vercel (в обзоре его не было среди
недостающих). После выкладки проверить, что он есть в ответе сайта.

Проверено на собранном сайте:

- заголовки есть у страниц, перенаправления `/admin` → вход, картинок из
  `public/`, `/api/artwork-thumbs`, карты сайта, 404 и файлов примерки;
- страница с другого адреса, встроившая вход в админку и главную, получила
  от браузера отказ («Refused to frame… frame-ancestors 'self'»);
- главная с видео, галерея, работа, примерочная, камера, контакты, «обо мне»,
  английская версия, вход — без ошибок в консоли, телефон и компьютер;
  «Скопировать ссылку» в «Поделиться» работает.

Не проверено отсюда: запуск Quick Look и Scene Viewer на настоящем телефоне.
Запрет камеры на них не действует — это отдельные программы телефона, а не
страница, — но после выкладки стоит один раз нажать «Примерить через камеру».

## О-13 · Шрифты — ✅ на сайте 22.10.2026

Замер на сайте: шесть файлов, 152 КБ, все загружаются заранее на каждой
странице. Cormorant обычный — 36 + 20 КБ (латиница, кириллица), курсив —

Сделано: убран курсив Cormorant (`lib/fonts.ts`). Он остался от девиза,
который теперь подчёркнут мазком, а на сайте не использовался нигде.
Стало четыре файла, 95 КБ — на 58 КБ (38%) меньше на каждой странице.

Чего обзор советовал, но не сделано, и почему:

- **вес 500 не убран** — Cormorant приходит одним файлом на оба веса,
  экономии ноль;
- **латиница на русских страницах осталась** — в её наборе пробел,
  цифры, знаки препинания и кавычки «», без неё не набрать ни одной
  русской строки;
- **английские страницы по-прежнему загружают кириллицу заранее**
  (34 КБ). Чтобы это убрать, нужна отдельная настройка шрифтов для
  английской версии; посетителей у неё мало — отложено.

Проверено: на 14 публичных страницах (русские, английские, примерочная,
вход в админку) до и после правки — курсива нет ни в одном элементе,

файлах, включая комментарии) — комментарий переписан, класса больше нет.

## О-15 · Content-Security-Policy — в ветке

`next.config.ts`, `contentSecurityPolicy()` — заголовок на каждый ответ
сайта вместо прежнего `frame-ancestors 'self'`:

| Правило                                                      | Зачем                                                        |
| ------------------------------------------------------------ | ------------------------------------------------------------ |
| `default-src 'self'`                                         | всё, что не названо ниже (видео, шрифты), — только своё      |
| `script-src 'self' 'unsafe-inline'`                          | скрипты с чужих сайтов не загрузятся                         |
| `img-src 'self' blob:` + домен бакета                        | домен — из `NEXT_PUBLIC_R2_PUBLIC_URL`, не разъедется        |
| `connect-src 'self' https://*.r2.cloudflarestorage.com`      | данные не уйдут на чужой сервер; загрузка фото из админки    |
| `object-src 'none'`, `base-uri 'self'`, `form-action 'self'` | без Flash, без подмены адреса страницы, форма — только к нам |
| `frame-ancestors 'self'`                                     | как в О-14: сайт нельзя встроить в чужую страницу            |

Строгий вариант с одноразовым ключом отвергнут: с ним Next собирает каждую
страницу заново на каждый заход, и О-1…О-11 пропали бы. Почему так —
ARCHITECTURE.md, §11.

**Найдено по пути:** Zod в примерочной пробовал `eval`, и каждый
посетитель получал ошибку политики в консоли. Zod теперь подключается
только через `lib/zod.ts` с `jitless` — это проверяет линтер.

**Сторож:** `npm run check:site` сверяет картинки, скрипты, стили, видео
и шрифты каждой страницы с её политикой (`scripts/site-check/csp.mjs`,
свои тесты). Проверено поломкой: без `'self'` в `img-src` проверка упала
на картинах, значках и фото художницы.

Проверено в Chrome без окна на боевой сборке и в режиме разработки:
главная с видео, галерея, категория, поиск, лента работы, «Повесить у
себя», примерочная с фото своей стены, старая ссылка на камеру, «обо мне»,
контакты, вход в админку, английская версия. Картины из бакета, видео,
шрифты и тёмный зал — без нарушений. Запрос к хранилищу Cloudflare
политика пропускает, запрос к чужому сайту — блокирует.

**Не проверено отсюда:**

- настоящая загрузка фото в админке — она пишет в боевые бакет и базу.
  После выкладки загрузить одно фото и посмотреть, что оно появилось;
- Quick Look и Scene Viewer на телефоне — это переходы в программы
  телефона, политика их не касается.
