# Архитектура сайта-портфолио художницы

Последнее обновление: 2026-09-05

## 1. Стек технологий

- **Next.js** (App Router) + **TypeScript** + **Tailwind CSS**
- **Prisma** + **PostgreSQL** (хостинг БД — Supabase)
- **NextAuth** — аутентификация для единственного админ-аккаунта
- Деплой — **Vercel**

## 2. Хранение изображений

**Cloudflare R2** — сразу, без промежуточного варианта на Supabase Storage.

Причины:

- нулевой egress (не платим за трафик отдачи изображений);
- S3-совместимый API (стандартные инструменты и библиотеки);
- не потребует миграции в будущем, если проект вырастет.

## 3. Модель данных

Реализована на этапе 3, схема — `prisma/schema.prisma`.

### `Artwork`

- `title` — название
- `description` — описание
- `category` — категория
- `technique` — техника
- `dimensions` — размеры одной строкой
- `year` — год
- `price` — цена
- `status` — `AVAILABLE` / `RESERVED` / `SOLD`
- `featured` — показывать ли на главной

### `Image`

- связь с `Artwork` (одна картина — много изображений)
- `isPrimary` — флаг главного изображения для превью

Фильтрация в галерее реализуется через Prisma `where` на сервере (категория, техника, цена, статус), без клиентской библиотеки для фильтров.

### Решения, принятые при реализации

**Цена — `Int` в целых рублях, а не `Decimal`.** У картин нет копеек, а `Decimal` из Prisma — не обычное число: его нельзя передать из серверного компонента в клиентский, Next не умеет его сериализовать. Понадобятся копейки или валюты — переходим на целые копейки, а не на `Decimal`.

**Порядок значений `ArtworkStatus` изменён на `AVAILABLE`, `RESERVED`, `SOLD`.** PostgreSQL сортирует enum в порядке объявления, а галерея сортирует карточки по статусу: сначала то, что можно купить, в конце проданное. Prisma такое изменение не мигрирует автоматически — сравнивает только набор значений, — поэтому миграция `status_order` написана вручную.

**Добавлено поле `featured`, которого не было в исходном списке.** Иначе `getFeatured` мог бы означать только «последние добавленные», а на первом экране должны стоять сильнейшие работы — выбирает их художница.

**Размеры оставлены одной строкой (`dimensions`), а не парой чисел.** Сортировки и фильтра по габаритам в плане нет, а разбор «60 × 80 см» на два числа потребовал бы формы с двумя полями и валидации ради ничего.

### Prisma 7: драйверный адаптер обязателен

В седьмой версии `PrismaClient` не подключается к базе сам — нужен адаптер (`@prisma/adapter-pg`), он создаётся в `lib/db.ts`. Свойства `url` и `directUrl` из схемы убраны: адрес для миграций задаётся в `prisma.config.ts`, адрес приложения передаётся адаптеру.

Клиент генерируется в `lib/generated/prisma` (в `.gitignore`) с опцией `importFileExtension = "ts"` — без неё сгенерированные файлы ссылаются друг на друга без расширений, что понимает сборщик Next, но не понимает голый Node, и `prisma db seed` падает.

## 4. Админка

Единственный админ-пользователь, аутентификация через NextAuth.

```
/admin                     — дашборд
/admin/artworks            — список работ
/admin/artworks/new        — добавление новой работы
/admin/artworks/[id]       — редактирование работы
```

## 5. Маршруты и структура страниц

Главная страница и история художницы разнесены по разным маршрутам: главная — визуальная, «галерея прежде всего», минимум текста; полная история — на отдельной странице `/about`.

```
/                     — визуальная главная: hero-картина, превью-галерея, тизер «о художнице»
/about                — полная история, путь/вехи, техника, портрет
/gallery              — галерея с фильтрами (категория, техника, цена, статус)
/gallery/[id]         — страница одной картины + кнопка «Связаться» (WhatsApp/почта)
/contact              — форма связи и контакты (решено: страница нужна)

/admin, /admin/artworks, /admin/artworks/new, /admin/artworks/[id] — админка (см. раздел 4)
```

Примечания:

- `/` не дублирует контент `/about` — только тизер со ссылкой «Подробнее» на `/about`.
- `/contact` **решено делать** (раньше значился опциональным). Причина: главный призыв сайта — кнопка «Заказать картину» в шапке, ей нужен адресат, а контактов в подвале для этого мало. В макете страница есть, с формой и блоком контактов.

## 6. Дизайн

Источник истины — макет из Claude Design. В репозитории: токены в
`design/tokens/organic.css`, эталонные страницы в `design/mockups/`.
Перенесённая в код версия — `app/globals.css`, витрина — `/styleguide`.

### Палитра

| Роль       | Значение  | Где                                      |
| ---------- | --------- | ---------------------------------------- |
| `bg`       | `#f5ead8` | фон светлых страниц                      |
| `surface`  | `#ebddc5` | карточки, поля ввода                     |
| `ink`      | `#201e1d` | текст                                    |
| `accent`   | `#c67139` | сиена — кнопки, ссылки, акценты          |
| `accent-2` | `#7a8a5e` | олива — второй акцент, статус «доступна» |

Плюс три тональных ряда по 9 шагов (`neutral`, `accent`, `accent-2`),
построенные в OKLCH на общей шкале светлоты.

### Типографика

**Literata** (заголовки) + **Manrope** (текст).

Изначально планировались Fraunces + Work Sans, в макете стояли Caprasimo +
Figtree. Ни один из этих четырёх шрифтов не имеет кириллицы — только
latin / latin-ext / vietnamese, — а сайт целиком на русском. Literata и
Manrope выбраны как ближайшие по характеру, но с полным кириллическим
набором. `--font-heading-weight` поднят с 400 до 600: Literata легче
Caprasimo и на 400 не держала бы вес заголовка в композиции.

### Приёмы

Вопреки раннему замыслу (бумажная текстура, рисованные разделители),
утверждённый макет строится на другом:

- **hero — видео во всю ширину**: 13-секундный ролик, после него слайды
  с работами, затем ролик заново. Мольберт с холстом, стоявший здесь
  раньше, убран: две крупные картины на одном экране спорили бы друг
  с другом;
- чередование светлых секций и **тёмных полос** во всю ширину (`neutral-900`);
- **тёплые радиальные свечения** по краям тёмных блоков;
- крупные **скруглённые панели** (32–40px), кнопки и метки — таблетки (999px);
- фильтр `washed` на репродукциях, чтобы фото не спорили с охрой интерфейса;
- пунктирные панели `panel-dashed` для пустых состояний.

### Статус

- свёрстаны: главная (`/`) и витрина дизайн-системы (`/styleguide`);
- макеты готовы, вёрстки нет: `/about`, `/gallery`, `/contact`;
- макеты есть, но разделов нет в плане: «Выставки», «Магазин», «Блог», «Пресса».
