# Стиль кода

Цель одна: **любой файл проекта должен выглядеть так, будто его написал
один человек за один вечер.** Разнобой в стиле стоит внимания на каждом
чтении — а читают код чаще, чем пишут.

Про язык кода и комментариев — [language.md](./language.md), про слои —
[architecture.md](./architecture.md).

## Форматирование не обсуждается

Ставит Prettier, настройки в `.prettierrc`: двойные кавычки, точки с
запятой, висячие запятые, ширина 100.

```bash
npm run format
```

Руками ничего не выравнивать и с форматтером не спорить. Не форматируются
только `design/` (эталон макета) и `lib/generated/` (переписывается
генератором) — они в `.prettierignore`.

## Импорты

Четыре группы, между ними пустая строка:

```ts
import path from "node:path";

import { PrismaPg } from "@prisma/adapter-pg";

import { db } from "@/lib/db";
import type { ArtworkWithImages } from "@/lib/artworks";

import { formatCaption } from "./caption";
```

1. встроенное в Node — с префиксом `node:`;
2. пакеты;
3. своё через алиас `@/`;
4. соседние файлы.

**Алиас `@/` вместо `../../`.** Относительный путь вверх ломается при
переносе файла и ничего не говорит о том, куда ведёт.

**Типы импортируются через `import type`.** Так видно, что импорт исчезнет
при сборке и не тянет за собой код.

## Имена

| Что              | Как          | Пример                          |
| ---------------- | ------------ | ------------------------------- |
| компонент и файл | `PascalCase` | `ArtworkImage.tsx`              |
| функция          | глагол       | `getArtworks`, `artworkCaption` |
| булево значение  | `is` / `has` | `isPrimary`, `hasPrice`         |
| тип              | `PascalCase` | `ArtworkFilters`                |
| файл с данными   | `kebab-case` | `demo-artworks.ts`              |

Имя файла компонента совпадает с именем компонента — иначе поиск по
проекту находит файл, но не находит определение.

Префикс `I` у интерфейсов не используем, `Type`/`Interface` в имени —
тоже. Тип и так виден по месту.

Сокращения только общепринятые (`id`, `url`, `alt`). `artwrk`, `img2`,
`tmpData` — нет.

## Типы

- **`any` запрещён.** Не знаешь тип — `unknown` и сузь проверкой.
- **`as` не используется, чтобы заткнуть ошибку.** Приведение типа — это
  обещание компилятору, за которое отвечаешь сам. Где можно — `satisfies`:
  он проверяет соответствие, но не стирает вывод.
- **Не переписывать руками то, что уже выведено.** Форма работы с
  изображениями берётся из схемы:

  ```ts
  export type ArtworkWithImages = Prisma.ArtworkGetPayload<{ include: typeof withImages }>;
  ```

  Ручной дубль разойдётся со схемой при первом же изменении модели.

- **У экспортируемой функции возвращаемый тип пишется явно.** Это и
  документация, и защита: случайное изменение формы результата упадёт
  здесь, а не в трёх местах вызова.

## Функции

- Одна функция делает одно.
- **Ранний выход вместо лестницы `if`.** Условие-отказ проверяется сверху
  и завершает функцию.
- Больше трёх аргументов — передавать объект. Три булевых подряд в вызове
  не читаются: `create(true, false, true)`.
- Значения по умолчанию — в сигнатуре (`getFeatured(limit = 6)`),
  а не через `||` в теле.
- Мутировать входные аргументы нельзя. Нужен изменённый результат —
  вернуть новый.

## Комментарии

Правило из [components.md](./components.md): комментарий объясняет
**почему**, а не что. Сверх этого:

- `/** ... */` над экспортируемой функцией, типом или полем схемы —
  одна-две строки о том, зачем оно и когда применяется;
- `//` внутри функции — только там, где решение неочевидно;
- **число с историей объясняется числом**: не «уменьшили размер», а «было
  1.64 МБ, стало 76 КБ, элемент шире 330px не рендерится»;
- закомментированный код не хранится. Он есть в git.

## Разметка

- Цвета, радиусы и тени — токенами ([design-system.md](./design-system.md)).
- Условные классы — через `lib/cn.ts`, не конкатенацией строк.
- Длинный список классов не разбивается вручную по строкам: этим
  занимается плагин Prettier для Tailwind, он же держит их в одном порядке.

## Асинхронный код

- `async/await`, не цепочки `.then()`.
- Независимые запросы запускаются параллельно через `Promise.all`,
  а не один за другим.
- `await` внутри цикла — только когда на то есть причина, и причина
  записана рядом. В `prisma/seed.ts` записи создаются по очереди намеренно:
  строка подключения ограничена одним соединением
  (`connection_limit=1`), параллельный `Promise.all` упёрся бы в него.

## Что проверяет машина, а что человек

| Проверка                                  | Чем              | Команда                |
| ----------------------------------------- | ---------------- | ---------------------- |
| форматирование                            | Prettier         | `npm run format:check` |
| границы слоёв, `process.env`, ошибки Next | ESLint           | `npm run lint`         |
| типы                                      | TypeScript       | `npm run typecheck`    |
| порядок импортов, имена, комментарии      | глазами на ревью | —                      |

Правило, которое можно поручить машине, **поручается машине**:
договорённость в тексте забывается через месяц, упавшая проверка — нет.
Появилось правило, которое линтер умеет проверять, — добавить его
в `eslint.config.mjs`, а не только сюда.
