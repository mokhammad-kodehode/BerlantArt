# Git

## Когда коммитить

- Коммит — **законченный смысловой шаг**, а не «сохранился на всякий случай».
  Этап плана, исправленный дефект, добавленная страница.
- **Не коммитить и не пушить без явной просьбы**, если это не оговорённая
  часть текущей задачи.
- Ветка `main`. Удалённого репозитория пока нет — это дыра, см. ниже.

## Что писать в сообщении

Строка-заголовок, пустая строка, затем **что изменилось и почему**.
Причина важнее перечисления файлов: файлы видно в диффе, а рассуждение —
только здесь.

Полезно включать:

- почему сделано именно так;
- какие варианты рассмотрены и отвергнуты;
- какие числа получились (было 1.64 МБ, стало 76 КБ);
- что осталось незакрытым.

Образец из истории проекта:

```
Мольберт в hero заменён фотографией вместо CSS-конструкции

Границы холста не подобраны на глаз, а измерены по пикселям файла.
Первый замер отсекал крайние столбцы порогом, и по бокам проглядывала
белая полоска незакрашенного холста — исправлено на полный размах.

Исходник весил 1.64 МБ — избыточно, элемент рендерится не шире ~330px.
Пережат в WebP: 76 КБ, в 21 раз легче.
```

## Перед `git add -A`

Посмотреть `git status` и убедиться, что не попали:

- `.env.local` и любые ключи;
- артефакты сборки (`.next/`, `tsconfig.tsbuildinfo`);
- временные файлы и черновики.

## Гигиена репозитория

- Переводы строк — `eol=lf` через `.gitattributes`, иначе Windows и Vercel
  расходятся и дают ложные диффы.
- Перемещая файл, использовать `git mv` — сохраняется история.
- Блок `nextjs-agent-rules` в начале `AGENTS.md` дописывается самим
  `next dev`. Удалять его бесполезно — он вернётся; коммитить вместе
  с работой.

## Открытый вопрос

**Удалённого репозитория нет.** Вся работа существует в одном экземпляре
на одном диске: поломка машины — и проект потерян. Завести приватный
репозиторий на GitHub стоит до того, как объём вырастет.
