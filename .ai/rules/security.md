# Секреты и приватность

## Секреты

- Настоящие значения живут **только в `.env.local`**. Этот файл в git
  не попадает.
- **Никогда** не просить прислать секрет в чат и не вставлять его
  в сообщение, коммит или комментарий.
- В `.env.example` — только плейсхолдеры и пояснения, что это и где взять.
  Файл специально разигнорирован в `.gitignore` (Next игнорирует `.env*`
  целиком), потому что это список переменных для новой машины.
- Пароль администратора хранится **хешем bcrypt в переменной окружения**,
  не в базе и не в открытом виде.

Перед каждым `git add -A` — посмотреть `git status` и убедиться, что в индекс
не попали `.env.local`, ключи, дампы.

## Переменные окружения

Новая переменная добавляется **сразу в два места**:

1. `.env.example` — с пояснением и пометкой, на каком этапе понадобится;
2. `lib/env.ts` — в схему Zod.

Схема выполняется при старте и при сборке — её импортирует `next.config.ts`
ради побочного эффекта. **Этот импорт не удалять:** без него валидация
существует на бумаге, сборка с пустым `DATABASE_URL` проходит успешно,
а падает уже прод в рантайме. Именно так и было до ревью.

`NEXT_PUBLIC_*` переменные попадают в браузер — туда нельзя класть ничего,
что не должно быть публичным. В `lib/env.ts` они перечислены явным объектом,
а не спредом `process.env`: Next подставляет их только там, где они написаны
буквально.

## Публичная папка

**Всё в `public/` доступно из интернета по прямой ссылке.** Проверено: файл
`public/artworks/README.md` отдавался с кодом 200 вместе со всем содержимым,
пока его не перенесли в `docs/`.

Туда не кладутся: заметки, черновики, документация, резервные копии,
служебные скрипты, файлы с внутренними договорённостями.

## Личные данные

- Контакты художницы публикуются только те, что она разрешила.
- Форма обратной связи не собирает лишнего: имя, способ связи, сообщение.
- Служебные страницы (`/styleguide`, `/admin`) закрываются от индексации.
