# Порядок работы

## Перед тем как назвать задачу сделанной

Три проверки, все должны пройти чисто:

```bash
npm run lint
npm run typecheck
npm run build
```

`build` без ошибок **не означает**, что страница выглядит правильно. Он
не видит съехавшую вёрстку, перекрытый текст и картину мимо холста.

## Проверка в браузере

Изменение видно на странице — **посмотреть его на странице**. Дев-сервер
запускается инструментом предпросмотра (конфиг в `.claude/launch.json`),
не через терминал.

Что смотреть:

- ошибки в консоли — но помнить, что там копятся старые записи с момента,
  когда файлы ещё дописывались; сверяться с логом сервера;
- вычисленные стили через JS — надёжнее скриншота, когда панель не отрисована;
- мобильную ширину 375px отдельно: горизонтальное переполнение, высота шапки;
- десктоп 1280px.

**Если проверить не удалось — сказать об этом прямо.** Панель браузера
временами зависает; тогда работают обходные пути: `curl` по разметке,
композиция через `sharp`, чтение логов сервера. Но выдавать непроверенное
за проверенное нельзя.

### Скрытая панель: пустые скриншоты и вечный скелет загрузки

Симптомы, которые выглядят как поломка сайта, но ею не являются:

- скриншоты приходят однотонными, хотя разметка на месте;
- страница с `loading.tsx` навсегда застревает на скелете, а настоящее
  содержимое лежит рядом в скрытом `<div>`.

Причина одна: панель скрыта, поэтому браузер замораживает кадры
(`requestAnimationFrame`), а React ждёт кадра, чтобы подставить пришедшее
содержимое вместо заглушки. Диагностика — одной командой:

```js
({
  видимость: document.visibilityState,
  raf: await new Promise((r) => {
    const id = requestAnimationFrame(() => r("идут"));
    setTimeout(() => (cancelAnimationFrame(id), r("ЗАМОРОЖЕНЫ")), 1200);
  }),
});
```

`visibilityState: "hidden"` вместе с замороженными кадрами означает, что
дело в панели, а не в коде. Что делать: проверять вычисленными размерами
через JS, сверять разметку через `curl`, а для страницы со скелетом —
временно убрать `loading.tsx`, тогда содержимое приходит сразу и меряется.
Скриншоты в этом состоянии бесполезны, и **говорить «проверено глазами»
про них нельзя**.

## Как прогнать код из `lib/` мимо браузера

Слой запросов удобно проверять напрямую, без страницы. Мешает одно: Node
не понимает алиас `@/` и не достраивает расширение `.ts`, как это делает
сборщик Next. Лечится хуком-резолвером во временной папке:

```js
// alias-hook.mjs
import { pathToFileURL } from "node:url";
const root = pathToFileURL("C:/Projects/ArtWebsite/").href;

export function resolve(specifier, context, next) {
  let spec = specifier.startsWith("@/") ? root + specifier.slice(2) : specifier;
  if ((spec.startsWith("file:") || spec.startsWith(".")) && !/\.[a-z]+$/.test(spec)) {
    spec += ".ts";
  }
  return next(spec, context);
}
```

Скрипт грузит переменные через `process.loadEnvFile` и зовёт функции
из `lib/artworks.ts` как есть. Так проверялись выборки и фильтр по
категориям. **Складывать такие скрипты в проект не надо** — им место
во временной папке сессии.

## Работа по этапам

План — в [ROADMAP.md](../../ROADMAP.md), 9 этапов по зависимостям. Завершив
этап, отметить его галочкой в разделе «Прогресс».

Этап заблокирован внешними данными (строки подключения, фотографии, тексты) —
сделать всё, что от них не зависит, и назвать конкретно, что нужно
от заказчика. Не останавливать работу целиком из-за одного пробела.

## Решения

- Развилка, где варианты дают заметно разный результат для заказчика, —
  спросить, но сначала сделать всё, что от ответа не зависит.
- Развилка с очевидным разумным вариантом — выбрать его, **сказать вслух**,
  что выбрал и почему, и продолжить.
- Принятое архитектурное решение — записать в
  [ARCHITECTURE.md](../../ARCHITECTURE.md), иначе оно забудется и будет
  переигрываться заново.

## Найденные по пути проблемы

Заметил дефект вне текущей задачи — сказать о нём, а не молча чинить и не
молча игнорировать. Мелкий и безопасный — починить и упомянуть. Крупный —
описать и дать заказчику решить.
