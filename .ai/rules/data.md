# Данные и база

> Этап 3 пройден: схема, миграции и слой запросов существуют. Страницы
> при этом ещё читают `lib/demo-artworks.ts` — переключение на базу идёт
> в составе этапа 4, тогда же временный файл будет удалён.

## Модель

`Artwork`: название, описание, категория, техника, размеры (`dimensions`,
одной строкой), год, цена, статус, флаг `featured`.

`Image`: связь с `Artwork`, `url`, `alt`, `isPrimary`, `order`. Одна
картина — много изображений, одно из них главное для превью.

Два места, где схема расходится с наивным ожиданием:

- **Цена — `Int` в целых рублях**, не `Decimal`. У картин нет копеек,
  а `Decimal` из Prisma — не обычное число: передать его из серверного
  компонента в клиентский нельзя, Next не умеет его сериализовать.
- **Порядок значений `ArtworkStatus` значим.** PostgreSQL сортирует enum
  в порядке объявления, галерея сортирует по статусу: `AVAILABLE`,
  `RESERVED`, `SOLD`. Переставишь строки в схеме — переставятся карточки.
  Prisma такое изменение сама не мигрирует (она сравнивает только набор
  значений), понадобится SQL руками — образец в миграции `status_order`.

## Prisma 7: обязателен драйверный адаптер

Главное отличие от того, что написано в большинстве руководств:
**`PrismaClient` в седьмой версии не подключается к базе сам**. Нужен
адаптер — у нас `@prisma/adapter-pg`, он создаётся в `lib/db.ts`.
Свойств `url` и `directUrl` в схеме больше нет.

Клиент генерируется не в `node_modules`, а в `lib/generated/prisma`
(папка в `.gitignore`, пересобирается командой `prisma generate`).
В генераторе стоит `importFileExtension = "ts"`: без него сгенерированные
файлы ссылаются друг на друга без расширений, и сборщик Next их понимает,
а голый Node — нет, из-за чего падал `prisma db seed`.

Версии `prisma`, `@prisma/client` и `@prisma/adapter-pg` держать
одинаковыми: они общаются по внутреннему протоколу.

## Подключение к Supabase

Две строки, и путать их нельзя:

| Переменная     | Порт                     | Для чего          |
| -------------- | ------------------------ | ----------------- |
| `DATABASE_URL` | 6543, transaction pooler | работа приложения |
| `DIRECT_URL`   | 5432, сессионный pooler  | миграции Prisma   |

К `DATABASE_URL` обязателен хвост `?pgbouncer=true&connection_limit=1`.

Проверено на этом проекте: `DIRECT_URL` указывает на тот же хост pooler'а,
только порт 5432, а не на `db.<ref>.supabase.co`. Миграции по нему проходят.

**Бесплатный тариф Supabase усыпляет проект после недели простоя.** Разбудить
можно только в панели, кнопкой. Пока проект спит, любая команда Prisma
падает с `FATAL: (ENOTFOUND) tenant/user ... not found` — это не про
неправильный пароль.

## Правила работы с базой

- **Клиент Prisma — синглтон** в `lib/db.ts`. Без этого в dev-режиме
  при горячей перезагрузке утекают подключения, и база упирается в лимит.
- **Фильтрация — на сервере через `where`**, не в браузере. Клиентская
  библиотека фильтров не нужна: состояние живёт в `searchParams`, ссылку
  на отфильтрованную выборку можно скинуть в мессенджер.
- Индексы под фильтры: `category`, `technique`, `status`, `price`,
  плюс `featured` под выборку для главной.
- Запросы собраны в `lib/artworks.ts`: `getArtworks(filters)`,
  `getArtworkById`, `getFeatured`. Страницы не пишут Prisma-запросы сами.
- После правки через админку — `revalidatePath`, иначе публичные страницы
  останутся со старыми данными.

## Наполнение базы

`prisma/seed.ts`, команда `npx prisma db seed` (прописана в
`prisma.config.ts`). Скрипт **ничего не делает, если работы в базе уже
есть**: база боевая, повторный запуск не должен плодить дубли и затирать
правки художницы.

Правило «не выдумывать фактов» ([content.md](./content.md)) действует и
здесь, причём строже: в базе выдумка живёт дольше, чем в вёрстке. В seed
попали пять работ — все, по которым есть фотографии, — с пустыми
размерами, годами и ценами.

## Аутентификация

Аккаунт один, поэтому **таблицы `User` нет**: логин и bcrypt-хеш пароля
лежат в переменных окружения. Таблица тут была бы лишней сущностью
и лишней поверхностью атаки.

Понадобится несколько аккаунтов — заводить таблицу сразу, мигрировать
задним числом дороже.
