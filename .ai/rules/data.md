# Данные и база

> **Это план, а не описание.** Ничего из перечисленного здесь ещё не
> существует: ни `lib/db.ts`, ни `lib/artworks.ts`, ни схемы Prisma.
> Раздел вступает в силу на этапе 3, пока данные лежат в
> `lib/demo-artworks.ts` — временном файле, который будет удалён.
>
> Значения портов, хвост `?pgbouncer=true&connection_limit=1` и требование
> отдельного `DIRECT_URL` взяты из общих знаний о связке Supabase + Prisma,
> **на этом проекте не проверены**. Перед этапом 3 сверить с тем, что
> реально отдаёт панель Supabase (**Connect → Prisma**) и с документацией
> Prisma — приоритет у них, а не у этого файла.

## Модель

`Artwork`: название, описание, категория, техника, размеры, год, цена,
статус (`AVAILABLE` / `SOLD` / `RESERVED`).

`Image`: связь с `Artwork`, `url`, `alt`, `isPrimary`, `order`. Одна
картина — много изображений, одно из них главное для превью.

Поля `demoArtworks` намеренно повторяют будущую модель: замена сведётся
к подмене источника, а не переписыванию разметки.

## Подключение к Supabase

Две строки, и путать их нельзя:

| Переменная     | Порт                     | Для чего          |
| -------------- | ------------------------ | ----------------- |
| `DATABASE_URL` | 6543, transaction pooler | работа приложения |
| `DIRECT_URL`   | 5432, прямое соединение  | миграции Prisma   |

К `DATABASE_URL` обязателен хвост `?pgbouncer=true&connection_limit=1`.
Без разделения миграции на serverless ломаются.

## Правила работы с базой

- **Клиент Prisma — синглтон** в `lib/db.ts`. Без этого в dev-режиме
  при горячей перезагрузке утекают подключения, и база упирается в лимит.
- **Фильтрация — на сервере через `where`**, не в браузере. Клиентская
  библиотека фильтров не нужна: состояние живёт в `searchParams`, ссылку
  на отфильтрованную выборку можно скинуть в мессенджер.
- Индексы под фильтры: `category`, `technique`, `status`, `price`.
- Запросы собраны в `lib/artworks.ts`: `getArtworks(filters)`,
  `getArtworkById`, `getFeatured`. Страницы не пишут Prisma-запросы сами.
- После правки через админку — `revalidatePath`, иначе публичные страницы
  останутся со старыми данными.

## Аутентификация

Аккаунт один, поэтому **таблицы `User` нет**: логин и bcrypt-хеш пароля
лежат в переменных окружения. Таблица тут была бы лишней сущностью
и лишней поверхностью атаки.

Понадобится несколько аккаунтов — заводить таблицу сразу, мигрировать
задним числом дороже.
